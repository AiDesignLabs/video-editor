# RFC 0004：片段素材替换

- 状态：已采纳
- 创建日期：2026-09-02
- 范围：P0-B 素材替换命令

## 1. 目标

提供一个可校验、可撤销的素材替换命令。调用方必须明确选择素材时长适配策略，命令不得在素材
过短或类型不兼容时静默改变播放行为。

## 2. 命令契约

`replaceSegmentAsset()` 接收片段 ID、素材 URL、素材类型、视频或音频时长，以及必填的
`strategy`。第一版只支持同类型替换：视频替换视频、音频替换音频、图片或贴纸替换图片。
文本、特效、滤镜和 3D 片段不支持素材替换。

视频和音频必须提供大于 0 的 `durationMs`。图片没有来源时长，只支持 `preserve`。

## 3. 适配策略

### `preserve`

只替换 URL，保留片段时间范围、`fromTime`、`playRate`、`reversed`、关键帧、变换、效果和
音频淡入淡出。视频和音频必须满足：

```text
fromTime + timelineDuration * playRate <= asset.durationMs
```

不满足时拒绝替换，协议和 History 均不变化。

### `fit`

视频和音频从新素材起点开始，以正常速度使用完整素材：清除 `fromTime`、`playRate` 和
`reversed`，并将片段时长设为 `asset.durationMs`。

- 主画面轨从被替换片段开始重建，后续片段保持连续。
- 非主轨继续使用现有的防重叠规则。
- 缩短片段时，超出范围的关键帧替换为新结束时刻的采样值。
- 音频淡入淡出分别限制为新片段时长的一半。
- 相邻转场时长限制为两侧片段时长的较小值。

## 4. 原子性与查询

替换、时间轴重建、关键帧处理和转场调整在一个事务内提交，产生一个 History 项，一次撤销完整
恢复。`canRun({ command: 'replaceSegmentAsset', input })` 使用同一组前置条件提供可读拒绝原因，
供界面和 agent 在执行前检查。

## 5. 暂不支持

- 循环素材。当前协议和渲染器没有循环字段，不能只在命令层模拟。
- 跨类型替换或自动转码。
- 稳定素材 ID、URL 重映射、代理素材关系和删除前引用检查。这些属于素材标识与资源生命周期的
  后续实现，不应混入片段时间适配事务。
