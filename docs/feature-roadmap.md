# 视频编辑功能路线图

本文记录编辑器已经具备的主要能力，以及后续版本需要补齐的功能。

## 定位与取舍原则

本仓库是**通用视频剪辑库**，不包含任何业务概念。消费方的业务字段通过
`SegmentExtraRegistry` / `TrackExtraRegistry` 模块增强挂载，不进入核心协议。

优先级不按"剪映有没有"来定，而按下面四条场景特征推导。**很多传统剪辑功能被有意降级，
不是遗漏**：

1. **素材可以低成本重新获取。** 不满意一段素材时，重新拿一条比反复雕琢它更快。因此
   "替换素材"这类操作的价值远高于变速曲线、滑移编辑、专业音频修复这类精修能力。
2. **编辑器嵌入宿主页面，而非独占整页。** 手势、快捷键、全局监听都可能与宿主冲突，
   并且需要支持同页多实例。这是库的责任，不能假设独占。
3. **未来由 agent 主导编辑，人类负责 review。** 参照 coding agent：绝大部分操作自动化，
   保留人工审阅和修改环节。这条改变的不是功能清单，而是**什么算完成** —— 见
   「Agent 可操作性」。
4. **长片以装配与 review 为目标，不做母版制作。** 15 分钟量级是明确目标；1~2 小时的
   装配和审阅可行，但最终调色、HDR 和母版输出不是 Web 的战场，交由专业软件完成。

状态说明：

- `已完成`：已有可用的协议、编辑命令、界面和渲染链路。
- `部分完成`：已有底层能力，但缺少完整的用户操作链路。
- `待实现`：尚未形成可用能力。

## 当前能力

以下能力已经具备，不列入后续开发范围：

- 画布元素的移动、缩放和旋转。
- 图片、视频和音频素材导入，以及本地资源存储。
- 视频缩略图和音频波形。
- 时间轴吸附、分割、复制、粘贴、重复和波纹删除。
- 轨道隐藏和静音。
- 转场库，以及外部转场和特效注册机制。
- 矩形蒙版、椭圆蒙版和色键。
- 关键帧协议、采样和渲染链路，以及音量淡入淡出和倒放。
- 工程保存、加载和删除。
- MP4、WebM 导出及基础导出参数设置。
- 修改画布尺寸：`commands.setCanvasSize()`、`CanvasSizePanel` 预设界面，预览按工程宽高比
  信箱化显示。
- 亮色 / 暗色双主题：`packages/ui/src/theme.css` 用 `light-dark()` 统一声明，宿主通过
  `data-theme` 或 `.ve-theme-dark` 切换，可作用于任意子树。

## P0：让 agent 和人都能可靠地编辑

### P0 交付门槛

P0 拆成三个顺序交付的门槛，避免所有基础能力集中在一个无法验收的大阶段：

- **P0-A：状态与产出正确。** 完成协议校验一致性、批量事务、History 整体撤销重做、导出错误
  传播和命令层测试。编辑失败时不得留下部分状态，导出成功时不得静默缺失音频或效果。
- **P0-B：Agent 可以安全提案。** 完成提案模型、命令与查询完备性、素材替换、多片段操作和
  语义化操作日志。提案在接受前不得修改主协议。
- **P0-C：宿主和长片可以稳定运行。** 完成多实例边界、性能基准、抽帧并发控制、时间轴
  虚拟化和代理素材基础链路。

只有前一个门槛通过验收，才进入下一个门槛；每个门槛都应能独立发布。

### Agent 可操作性

**状态：待实现。** 这一节是 P0 的组织主线。人类可以用鼠标绕过 API 缺口，agent 不能 ——
命令层没有的能力就是能力天花板。

这些工作同时也是测试、历史界面和协作的基础设施，即使 agent 路线推进慢于预期也不会白做。

**命令完备性。** `editor-core.commands` 当前覆盖片段增删改、移动、裁剪、分割、转场、
轨道显隐、画布尺寸和撤销重做。缺口：

- `setFps`：`videoBasicInfo.fps` 可写且已进历史，但没有命令入口、校验和界面。fps 影响
  逐帧步进和导出的采样时刻，但不改变以毫秒表示的关键帧时间语义。应与画布尺寸合并为一组
  工程属性命令。
- 轨道结构：新增、删除、重排。
- 关键帧：新增或更新、移动、删除单个关键帧，以及修改缓动。
- 批量操作入口，见下一节。

**查询完备性。** `editor.selectors` 当前只有 `getSegment`、`getTrackById`、
`getTrackBySegmentId`、`getTracks`。agent 必须先理解才能编辑，缺少查询层就只能拿整个协议
自己解析 —— 等于把时间轴规则实现两遍，两边必然漂移。需要补齐：

- 按时间点查询：某时刻有哪些片段、播放头落在哪个片段内。
- 结构查询：轨道空隙、相邻片段、重叠冲突、总时长。
- 属性采样：某时刻某属性的生效值，区分静态值、关键帧值和插值结果。
- 选中态与可执行性查询：当前选中、某个命令此刻是否可执行及原因。

**语义化操作日志。** History 记录的是 immer patch，人类看不懂，无法据此审阅 agent 的提案。
需要在事务上附带语义描述（例如 `split-segment`、`replace-source` 及其参数），用于：

- 向人类展示"agent 打算做什么"，支撑提案 → 审阅 → 接受/拒绝的流程；
- 未来的历史记录界面；
- 审计与调试。

语义标签不参与撤销语义本身，只作为元数据，也不能直接作为确定性回放格式。未来如需回放，
需要另外定义带版本的操作协议、前置条件、基础工程版本和确定性 ID 生成规则。

**提案与提交分离。** Agent 提案不是 History 中尚未撤销的一次编辑。提案需要在临时协议上执行，
主协议在接受前保持不变：

1. 提案记录 `baseRevision` 和语义化操作列表。
2. 命令在基础工程的隔离副本上执行，生成可预览的临时协议、校验结果和变更摘要。
3. 拒绝提案时直接丢弃临时状态，不调用 `undo()`。
4. 接受提案时检查主协议仍处于 `baseRevision`；版本已变化则要求重新生成或解决冲突。
5. 通过检查后，将全部操作作为一个原子事务提交，并生成一个 History 项。

验收标准：

- 界面上能做到的每一个编辑操作，都有对应的命令，不需要直接改协议。
- 给定一个协议和一个时间点，可以只通过 selectors 回答"此刻画面上有什么、能做什么"。
- 一次 agent 提案可以完整展示为人类可读的操作列表，并整体接受或整体拒绝。
- 拒绝提案不会修改主协议、undo 栈或 redo 栈；接受提案只增加一个 History 项。
- 审阅期间主协议发生变化时，旧提案不能直接覆盖新状态。

### 批量命令与历史事务

**状态：待实现。** 当前 `useHistory()` 每次调用 `update()` 都会立即生成一个独立历史项，
无法把多个命令或连续拖拽更新合并成一次用户操作。

在 agent 场景下这条的定位变了：不只是"批量编辑更方便"，也是**已接受的 agent 提案必须原子
提交并能整体撤销**的前提。提案接受或拒绝由独立提案模型负责；History 只管理已经提交的状态。
一次替换素材要同时改 url、时长、转场和关键帧，用户撤销一次不能只回退一半。

需要同时支持两类事务：

- **批量命令事务**：批量移动、删除、复制、组合和轨道操作在一个原子事务中完成。任一步失败
  时，整个事务回滚。
- **连续交互事务**：画布拖拽、时间轴拖动、裁剪和关键帧移动可以实时更新预览，但从按下到
  松开只生成一个历史项。取消交互时恢复开始前的状态。

History 需要满足：

- 一个成功事务只压入一个 `UndoStackItem`；一次 `undo()` 或 `redo()` 必须整体回退或重放
  全部修改。
- 空事务不生成历史记录。事务提交后才清空 redo 栈；取消或失败不得影响现有 undo/redo 状态。
- 嵌套事务复用最外层事务，不允许内部事务提前提交一部分历史。
- 事务中的状态更新仍然保持响应式，保证拖拽预览、时间轴和渲染器可以实时刷新。
- 事务提交前统一执行协议校验；校验失败时回滚到事务开始前的状态，并返回明确错误。
- 工程协议之外的异步副作用不进入 History。资源写入、上传和导出等任务应在事务成功后启动，
  并使用独立的取消和补偿机制。
- 事务可携带语义标签和元数据，供 agent 提案审阅和历史界面使用。

`editor-core.commands` 应提供稳定的批量操作入口，避免界面连续调用多个底层命令拼接业务操作。
协议层需要提供明确的事务 API，但具体命名在实现前通过 RFC 确定。

验收标准：

- 同时移动多个片段后，一次撤销可以恢复所有片段的位置。
- 连续拖拽产生多次中间更新，但 undo 栈只增加一项。
- 批量操作中途失败后，协议状态、undo 栈和 redo 栈均保持操作前状态。
- 事务中的新增、删除、ID 替换、转场同步和主轨重排可以整体撤销、重做。
- 嵌套事务、空事务、取消事务和提交后新增编辑均有单元测试覆盖。

### 宿主集成边界

**状态：待实现。** 编辑器嵌入宿主页面，手势、快捷键和全局监听都可能与宿主冲突，并且需要
支持同页多实例。当前这些行为在组件内写死。

需要明确并开放：

- **手势策略可配置。** 滚轮、触摸板捏合缩放当前在组件内直接 `preventDefault` 并
  `stopPropagation`，宿主无法关闭或改写。需要提供开关与传播策略，让宿主自行仲裁。
- **快捷键作用域。** 明确快捷键在什么焦点范围内生效，避免多实例或宿主输入框中误触发。
- **全局监听的归属。** 拖拽期间在 `window` 上注册的 mousemove / mouseup 需要定义多实例
  语义与清理时机。
- **渲染器实例策略。** `createRenderer({ app })` 已经允许宿主注入自己的 Pixi Application，
  这是多实例共享或池化的既有入口，需要写成明确契约并文档化。同时要给出上限指引：浏览器
  的 WebGL context 数量有限，每实例独占一个 Application 在多开时会耗尽。
- **模块级注册表语义。** `registerEffect` / `registerTransition` 是模块单例，多实例之间
  共享。这可能是期望行为，但必须写明，并明确注销时机。
- **只读模式。** 只读时禁用所有编辑入口与拖拽，但保留播放、缩放和查询。

验收标准：

- 宿主可以完全接管滚轮与捏合手势，编辑器不再拦截。
- 同页两个实例可以独立编辑、独立撤销，互不干扰快捷键与拖拽。
- 多实例下渲染器资源有明确的共享或释放策略，不会因 WebGL context 耗尽而失败。

### 替换素材与素材标识

**状态：待实现。** 素材可低成本重新获取，因此"换一条素材"是高频操作，优先级高于对单条
素材的精修。

- 提供替换片段素材的命令。变换、效果等与来源时长无关且仍兼容的属性可以保留；时间范围、
  `fromTime`、`playRate`、倒放窗口、关键帧和相邻转场必须经过新素材边界校验。
- 命令必须显式接收素材适配策略，例如拒绝替换、裁短现有片段、调整片段时长或循环素材。
  支持哪些策略及其默认值需要在实现 RFC 中确定，不能静默选择。
- 新旧素材类型不兼容时应拒绝替换，除非调用方明确选择了可验证的转换路径。
- 裁短或调整时长时，需要定义关键帧重建、淡入淡出、转场时长和主轨后续片段移动规则。
- 当前片段直接保存 `url`。需要明确稳定的素材标识与实际资源地址的映射关系，使素材地址变化
  时无需重写工程内所有片段。
- 删除素材前需要检查工程引用，避免留下无法恢复的片段。
- 原始素材、代理素材、缩略图和波形应共享可追踪的来源关系及缓存失效规则。
- 替换必须是一个原子事务，一次撤销完整回退。

### 导出任务可靠性

**状态：部分完成。** 当前已有导出参数、进度、成功结果和错误显示，合成层也提供取消编码和
释放资源的基础能力，但还没有统一的导出任务生命周期。

需要完成：

- 将一次导出表示为独立任务，明确等待、运行、成功、失败和取消状态。
- 用户可以取消正在运行的导出；取消后停止解码、渲染和编码，并释放临时资源。
- 防止重复启动同一个导出任务，页面关闭或切换工程前明确提示正在运行的任务。
- 失败时保留导出参数和可读错误，允许直接重试，不要求用户重新填写。
- 导出使用启动时的工程快照，避免编辑过程中的协议变化造成同一文件前后内容不一致。
- 导出结果、错误和任务状态与具体界面解耦，业务应用可以自行选择抽屉、弹窗或任务中心展示。
- 导出 API 提供可等待的完成结果；后台编码错误必须传播到任务状态，不能只写入控制台。
- 请求包含音频时，任何必要音轨加载或混音失败都必须使任务失败，不能静默产出无声视频。
- 成功状态表示视频、请求的音频和支持的效果均已写入结果；不支持的能力在启动前明确报错。

导出预设、任务队列和历史记录属于 P1。后台导出的能力取决于浏览器运行环境，需要单独验证，
不作为 P0 完成条件。

### 长片可扩展性

**状态：部分完成。** 渲染器已有局部显示对象缓存和资源销毁逻辑，但目前没有可重复的基准证明
编辑器在目标规模下可用。长片目标拆成两个档位，不能用同一组验收标准：

- **编辑档：15 分钟量级。** 支持正常播放、定位、拖拽、裁剪和预览，作为完整编辑能力的主要
  性能目标。
- **装配审阅档：1～2 小时。** 重点支持导入、快速定位、分段播放、变更审阅和局部修改；是否
  要求全片连续实时播放和浏览器内一次性导出，需要业务另行确认。

每个档位都要明确目标设备、轨道数、片段数、素材分辨率、操作延迟、播放稳定性、内存峰值和
资源释放要求。现有“约 30 个片段”的工程只能作为观察样本，不能作为性能结论。

agent 主导会改变负载形态：人类主要在**审阅**而非逐帧刮擦，需求偏向快速定位、跳转到变更处、
分段播放和差异高亮，而不是长时间连续实时播放。这反而降低了长片在 Web 上的难度。

需要实现：

- **抽帧并发控制。** `generateThumbnails` 当前按包含 URL、尺寸、时间范围、步长和资源目录的
  请求键去重，但没有全局并发上限。大量不同请求同时进入视口仍可能一次性拉起大量解码器。
  波形提取也需要单独核对并发去重和全局限制，不能直接假设与抽帧实现相同。
- **时间轴虚拟化。** 只渲染可见范围及必要缓冲区，避免工程长度直接增加 DOM 与缩略图开销。
- **代理素材。** 生成、状态管理和原始素材切换；预览使用代理，导出默认使用原始素材。对长片
  是前提而非优化。
- **分段合成与检查点恢复。** 长片单次导出失败会使已有工作失效，但当前合成链路是一条连续
  编码流，不能直接恢复。实现前必须通过独立 RFC 定义视频关键帧边界、时间戳连续性、音频分段
  混合、MP4/WebM 封装与合并、中间产物存储、版本和缓存失效规则。该 RFC 通过前，不把检查点
  恢复作为 P0-C 完成条件。
- 明确视频解码器、纹理、音频缓冲、缩略图和波形的内存预算，以及超出预算后的回收顺序。
- 建立预览渲染缓存及失效规则；片段内容、效果、画布尺寸或依赖素材变化时，只使受影响的缓存
  失效。
- 异步解码和素材分析任务支持取消，快速拖动播放头或切换工程时不继续占用资源。
- 建立可重复的性能基准工程，覆盖长视频、多轨道、多片段、关键帧、转场和高分辨率素材。目标
  设备和验收阈值由业务环境确认。

性能验收必须同时检查操作延迟、播放稳定性、内存峰值和资源释放，不能只比较首次加载时间。

### 多片段与关联编辑

**状态：待实现。**

需要实现：

- 框选、追加选择和取消选择多个片段。框选需要与宿主页面的框选行为协调，见「宿主集成边界」。
- 批量移动、删除、复制和调整公共属性。
- 组合与取消组合片段。
- 关联与取消关联视频、音频片段，移动和裁剪时保持同步。配音与画面绑定在本场景下频次很高。

### 轨道管理

**状态：部分完成。** 当前支持轨道隐藏和静音。

需要实现新增、删除和重排轨道，并接入撤销重做。

轨道锁定与音频独奏降到 P1：轨道结构在本场景下简单且相对固定，这两项是低频操作。

## 需要提前设计的基础能力

以下内容不要求立即完成全部界面，但会影响协议、编辑命令和工程兼容性。应先确定数据边界和
行为规则，再继续扩展时间轴功能。

### 多选、组合与关联的数据边界

- 多选属于编辑器会话状态，不写入工程协议；重新打开工程时不恢复选中状态。
- 组合和音视频关联属于工程数据，需要稳定的持久化标识。
- 需要明确组合、关联、转场同时存在时，移动、裁剪、删除和复制的传播规则。
- 暂不引入嵌套时间线或复合片段，除非业务确认需要独立子工程语义。

### 轨道生命周期与时间轴规则

- 在实现新增、删除和重排轨道前，明确主画面轨道不可删除、主轨无间隙、同类轨道重叠和空轨道
  清理规则。
- 统一覆盖、插入、波纹、吸附和碰撞处理语义，避免不同拖拽入口产生不同结果。
- 锁定、隐藏、静音和独奏应由命令层执行一致的权限和播放规则。

### 工程版本与迁移

- `version` 不应只用于校验。协议结构发生变化时，需要按版本顺序执行迁移。
- 迁移必须保持幂等，即重复执行不会继续改变结果，并保留未知的扩展字段。
- 保存失败、迁移失败和资源缺失需要给出可恢复的错误，不得静默创建空工程覆盖原数据。

### 异步任务模型

- 素材导入、元信息读取、缩略图、波形、代理生成和导出都应使用统一的任务状态：等待、运行、
  成功、失败和取消。
- 任务需要统一的进度、取消、重试和错误接口，并在工程切换或编辑器销毁时释放资源。
- 任务结果写回工程前需要确认目标工程和片段仍然有效，避免过期任务覆盖新状态。

### 预览与导出一致性

- 新增关键帧属性、变速、蒙版、转场或音频处理时，必须同时定义预览和导出路径。
- 时间采样、裁剪边界、缓动和音量合成使用共享的纯函数，避免两条链路各自实现规则。
- 不支持的解码或渲染能力应尽早报错，不允许预览正常但导出静默缺失效果。

## 工程质量与对外契约

这些不是终端用户功能，但直接决定这个库能否被宿主直接使用。

### 界面回归策略

**状态：待实现。** 这是当前最薄弱的一环。类型检查和单元测试无法发现界面失效 —— 样式被
覆盖、事件没接上、图标名写错，全都不报错。

已经发生过的静默失效包括：`:where()` 让组件样式与 CSS reset 同权而丢失内边距；
`--at-apply` 中的 UnoCSS 任意值被格式化破坏；引用了不存在的图标名；缩放滑块的
`update:zoom` 无人监听；片段并排渲染了两个相同标签；容器宽度计算溢出导致恒定横向滚动条。
这些都通过了类型检查和全部单元测试。

需要建立：

- 关键交互的冒烟测试：选中、拖拽、缩放、分割、撤销等路径可达且产生预期协议变化。
- 关键计算属性断言：元素尺寸、是否溢出、样式是否被外部 reset 覆盖。
- 图标名存在性校验，避免引用未注册的图标。
- 已有的 `style-specificity.test.ts` 是这一类防线的雏形，应继续扩展。

不要求引入完整视觉回归，但必须有一层能拦住"样式静默消失"。

### 文案与国际化

**状态：待实现。** `packages/ui` 当前所有文案都是硬编码中文（`宽`、`高`、`抽帧中…`、
`生成失败`、`静音轨道`、`添加转场` 等），没有任何 i18n 机制。宿主应用普遍使用自己的
i18n 方案，当前只能通过覆盖 slot 或分叉来本地化，与"宿主可直接使用"的目标冲突。

需要提供文案注入或 i18n 适配层，并保证所有内置文案可被替换。

### 命令层测试覆盖

**状态：待实现。** `editor-core` 是文档中明确的"最小稳定 API"层，当前**没有任何测试文件**
（protocol 11 个、renderer 22 个、ui 10 个、shared 1 个）。命令层是 agent 的唯一入口，
必须有覆盖。

### 协议校验一致性

**状态：待实现。** 校验规则目前分散在两处且不一致：JSON Schema 中 `width` / `height` 的
下限是 `0`，而 `setCanvasSize` 命令要求至少 `2`。`0` 能通过校验但无法编码出视频。

约束应收敛到 Schema，使绕过命令直接写入协议也无法构造非法工程。

## P1：增强编辑效率

### 素材拖入时间轴

**状态：部分完成。** 素材可以导入并添加到工程，但缺少从素材面板直接拖入目标轨道和目标
时间的完整交互。

需要实现拖入预览、目标轨道提示、时间位置计算、不合法目标提示，以及与时间轴吸附规则的统一
处理。

### 关键帧编辑体验

**状态：部分完成。** 协议、校验、插值、片段分割重建、预览和导出链路已经具备。当前界面只能
在播放头处添加关键帧、显示合并后的菱形标记，以及清空片段的全部关键帧。

命令与查询部分已并入「Agent 可操作性」。界面部分需要：

- 时间轴标记保留属性身份，支持选择、拖动和删除，不能只按时间合并成不可操作的菱形。
- 移动关键帧、画布拖拽和连续参数修改使用历史事务，一次操作对应一个撤销步骤。
- 删除某个属性的关键帧后，明确恢复静态值的规则，避免画面突然跳变。

右侧属性面板的具体布局、控件和自动打帧方式需要等待业务定义。完整曲线编辑器和空间运动路径
继续作为后续能力。

### 画面裁剪与镜像

**状态：待实现。** 当前变换能力覆盖位置、统一缩放和旋转，但缺少素材内部裁剪和水平、垂直
镜像。生成素材的构图不一定理想，裁剪在本场景下仍有价值。

需要先明确裁剪框使用素材坐标还是画布坐标，以及裁剪、`fillMode`、蒙版、旋转和关键帧的计算
顺序。预览、Gizmo 和导出必须使用同一套几何规则。

### 时间轴导航

**状态：待实现。**

- 时间轴标记和入点、出点范围。
- 上一帧、下一帧、跳转到片段边界和选区循环播放。
- 更清晰的吸附目标提示和冲突反馈。

审阅长片时这些导航能力比精修剪辑手法更重要。

### 字幕文件互转

**状态：待实现。** SRT、ASS、VTT 的导入与导出，主要服务交付环节。

各格式的能力差异需要在导入时显式处理，不静默丢弃无法表示的信息。接入前需要先确定字幕是
独立片段类型、独立轨道类型，还是带字幕元数据的文本片段，并保证普通标题文本不被字幕批量
操作误修改。

### 轨道锁定与音频独奏

从 P0 降级。轨道结构简单固定时属于低频操作。独奏与静音同时存在时的规则需要在实现前明确。

### 导出预设与任务队列

导出预设、任务队列和历史记录，建立在 P0 的导出任务生命周期之上。

### 素材管理

素材文件夹、搜索、筛选和标签；重复素材识别；离线素材提示和重新关联；工程打包时收集所需
素材。

投入规模取决于用户是否会大量混入外部素材，需要业务确认后再细化。

## P2：精修与高成本能力

以下能力服务的是"对同一条素材反复雕琢"。在素材可低成本重新获取、且 agent 主导编辑的前提
下，它们的使用频次显著低于装配类操作，因此整体降级。**这是有意取舍，不是遗漏。**

### 变速曲线

**降级理由：** 素材时长主要由生成参数决定，重新获取一条合适时长的素材通常比调整速度曲线
更快。详细设计见 [RFC 0003：Speed Curves](./rfcs/0003-speed-curves.md)，实现时需要覆盖
速度关键帧、时间与源时间映射、分割裁剪后的曲线重建，以及预览与导出一致性。

### 精修剪辑手法

**降级理由：** 滑移、滑动和滚动编辑用于在不改变总时长的前提下微调素材内容边界，前提是
素材冗余充足。生成素材的边界通常直接由生成决定。

### 专业音频处理

**降级理由：** 分离视频音频、轨道混音、自动闪避、人声录制、均衡器和降噪主要解决实拍收音
问题。保留音高的变速与变速曲线一并评估。

### 高级蒙版

**降级理由：** 自由路径蒙版、控制点编辑、蒙版关键帧和运动跟踪属于重量级精修。基础的矩形、
椭圆蒙版和色键已经具备。背景移除和对象分割属于独立的智能处理能力，不与基础蒙版编辑绑定。

### 高成本媒体处理

光流慢动作和帧插值、后台预渲染和跨会话渲染缓存。

## 建议实施顺序

1. 完成 P0-A：统一协议约束，实现批量事务与 History 整体回退，补齐导出错误传播和命令层测试。
2. 完成 P0-B：定义提案模型，补齐命令与查询，完成素材替换、多片段操作和语义化日志。
3. 完成 P0-C：明确宿主多实例边界，建立分级性能基准，实现抽帧并发控制、时间轴虚拟化和代理
   素材基础链路。
4. 为分段合成与检查点恢复编写 RFC；在容器、音频和中间产物方案确定后再排实现版本。
5. 完成轨道管理、素材拖入时间轴、导出预设与任务队列，以及界面回归策略。
6. 补齐关键帧编辑体验、时间轴导航、画面裁剪与国际化。
7. 视业务需要再推进 P2 的精修类能力。
